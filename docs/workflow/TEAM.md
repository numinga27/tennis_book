# Канонические роли

| Чат | Ответственность | Основная зона |
|---|---|---|
| tennis_book — оркестратор | очередь, зависимые этапы, приёмка, checkpoint | docs/workflow/ |
| tennis_book — продукт и ТЗ | процессы центра, MVP, критерии и решения | docs/product/ |
| tennis_book — сайт | существующие web views/forms/templates по контрактам | web-слой tennis_booking/ |
| tennis_book — приложение | аудит вариантов мобильного клиента, затем утверждённая реализация | будущая mobile-зона |
| tennis_book — backend и интеграции | модели/доступы/бронь/API/платежные адаптеры | серверные части tennis_booking/ |
| tennis_book — QA и поставка | независимые проверки, воспроизводимый запуск, инструкции | tests и docs/qa/, docs/delivery/ |

Точные ID — в локальном .codex-local/project-chats.json, не в публичных документах. Эти зоны пересекаются в существующем Django monolith: перед задачей оркестратор перечисляет конкретные файлы и единственного writer. Создание ролей не разрешает параллельную правку всего monolith.

Оркестратор и сложные роли — Astra medium; high для конкретного рискованного этапа. Глобальный лимит двух обычных исполнителей сохраняется. Новые чаты после регистрации отвечают одной фразой о готовности и останавливаются. Дальнейшие работы выдаются отдельно.
