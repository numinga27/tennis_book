# План восстановления

1. Организация: clone, неизменный baseline, отдельный проект и шесть чатов с readback, локальный реестр.
2. Воспроизводимость: определить и закрепить зависимости, безопасную dev-конфигурацию и синтетические данные; проверить Django check/тесты и локальный старт без изменения исходной БД. Не обещать запуск до результата.
3. Аудит одного сценария: расписание → бронь → кабинет → отмена; права и конфликты брони, стоимость/статусы. Короткий отчёт о фактах, не общий rewrite.
4. Согласовать MVP сайта/мобильного клиента, дизайн и нужные платформы; архитектурное решение об общем backend и API.
5. Реализовать один вертикальный срез, проверить web/mobile на согласованных устройствах. Платежи/уведомления только в разрешённых тестовых окружениях.
6. Укрепить безопасность/конкурентность/восстановление данных, подготовить релизные артефакты и понятный handoff. Production и магазины — отдельный gate.

Существующие этапы не повторять без причины. Каждый checkpoint — evidence, оставшееся, блокер и один следующий шаг. Не запускать все роли одновременно.
